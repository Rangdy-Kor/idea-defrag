# NextShell

---

- **핵심 아이디어**: Node.js와 WASM으로 셸 스크립팅 언어를 개발
- **문법**:
  - **파이프라인**: 데이터를 텍스트가 아닌 JSON 스트림으로 전달
  - **변수 할당 및 제어**: let을 사용하고 블록 스코프를 가진다. 상수의 선언은 const를 사용한다. 블록 스코프를 가진다.
  - **외부 모듈 호출**: `use` 키워드로 npm 패키지를 셸 내장 모듈처럼 불러온다.
  - **비동기 처리**: 기본적으로 모든 연산은 `await`가 생략된 비동기 스트림으로 동작한다. `await`의 명시 없이 스크림이 완료될 때까지 자동으로 파이프가 연결된다.
- **아키텍처**: 크게 3가지 계층으로 구성된다.
  - **계층 1**: 런타임 셸
    - **Parser & Evaluator**: 사용자가 입력한 구문을 AST로 변환하고 실행한다.
    - **REPL**: Node.js의 `readline`를 활용하여 입력을 받고, 비동기 스트림을 관리한다.
  - **계층 2**: 스트림 엔진
    - 모든 명령어는 `Node.js Transform Stream`을 상속받는다.
    - 명령어간의 데이터 전달은 JSON 직렬화를 거쳐 스트림으로 흐르며, 이는 메모리 효율적으로 동작한다.
  - **계층 3**: WASM 브리지
    - 고성능 계산이나 리소스가 많이 드는 작업은 Rust로 작성된 WASM 모듈로 넘긴다.
    - Node.js 환경과 WASM 메모리 간의 공유 버퍼를 활용해 성능 오버헤드를 최소화한다.
- **데이터 흐름 예시**:
  - 사용자가 `ls | where name == "*.log"`를 실행할 때:
    1. **Parser**: `ls` 명령어와 `where` 명령어를 파싱하여 각각 대응하는 Node.js 스트림 객체를 생성한다.
    2. **Stream**: `ls` 객체가 파일 리스트 객체를 생성하여 스트림에 입력(`push`)한다.
    3. **Bridge**: `where`는 스트림을 순회하여 조건 검사를 수행한다.
    4. **Output**: 최종 필터링된 데이터가 사용자 터미널에 객체 형태(또는 텍스트 포맷팅)로 출력된다.
